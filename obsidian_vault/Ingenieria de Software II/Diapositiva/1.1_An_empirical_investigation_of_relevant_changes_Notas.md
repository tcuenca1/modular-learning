# An empirical investigation of relevant changes and automation needs in modern code review

**Autores:** [DOCENTE] 1, [ESTUDIANTE] 2

**Institución 2:** University of Zurich, Zurich, Switzerland

**Publicación:** Empirical Software Engineering (2020) 25:4833–4872 | https://doi.org/10.1007/s10664-020-09870-3

## Abstract

La investigación reciente muestra que las herramientas disponibles para la [[Revisión de Código Moderna]] ([[MCR]]) están lejos de cumplir con las expectativas actuales de los desarrolladores. El objetivo de este artículo es investigar los enfoques y herramientas que aún se necesitan para facilitar las actividades de [[MCR]]. 

Para lograrlo, se llevaron a cabo los siguientes pasos:
1. Se elicitó empíricamente una taxonomía de tipos de cambios de revisión recurrentes que caracterizan la [[MCR]] (denominada modelo CRAM).
2. Se integraron tópicos y tipos de cambio de [[MCR]] de la literatura existente.
3. Se encuestó a 52 desarrolladores para integrar tipos de cambio faltantes.
4. Se evaluó de forma cualitativa la relevancia y completitud de los cambios identificados mediante 14 participantes adicionales (desarrolladores e investigadores) y 21 desarrolladores para evaluar la viabilidad de utilizar técnicas de resumen ([[Natural Language Processing|NLP]]).

---

## 1. Introduction

La [[Revisión de Código Moderna]] ([[MCR]]) es una variante de la revisión de código tradicional caracterizada por ser informal y estar soportada por herramientas (ej. [[Gerrit]], [[CheckStyle]], [[PMD]]). Durante la [[MCR]], los desarrolladores buscan mejorar la calidad de los parches mediante la corrección de errores, la adherencia a convenciones de estilo y la mantenibilidad.

### Preguntas de Investigación (Research Questions)
- **RQ1:** *What types of changes occur during MCR?* (¿Qué tipos de cambios ocurren durante la MCR?)
- **RQ2:** *What are the emerging automation needs of developers in MCR?* (¿Cuáles son las necesidades emergentes de automatización de los desarrolladores en MCR?)

## 3. Results

### 3.1 RQ1: Types of changes occuring in modern code reviews
Se desarrolló el modelo **CRAM** (*Code Review chAnges Model*), una taxonomía estructurada en dimensiones de alto y bajo nivel:
- Tipo de artefacto involucrado (código de producción, pruebas, archivos de configuración).
- Tipo de actividad realizada (mantenimiento prefectivo, correctivo, etc.).
- Categorías específicas de cambio (Estructura, Documentación, Estilo, Lógica, Funcionalidad, Recursos, Concurrencia, etc.).

> **Tabla detectada:** Las Tablas 4 y 5 (y 20 y 21 en el apéndice) detallan la taxonomía CRAM, clasificando los cambios en artefactos de código de prueba/producción y otros artefactos no relacionados directamente con el código fuente (como configuraciones de integración continua [[Continuous Integration|CI]], archivos de entrega continua [[Continuous Delivery|CD]], archivos de Docker, etc.).

### 3.2 RQ2: Emerging automation needs in MCR
- El 98% de los desarrolladores encuestados cree que ciertas tareas son difíciles de automatizar (como la detección de defectos complejos), mientras que otras (como la generación de cabeceras de licencias) deberían automatizarse mediante [[Sistemas de Recomendación]].
- Existe una alta demanda de herramientas para detectar y generar parches para problemas de rendimiento, consumo de recursos y seguridad.
- Se exploró el uso de técnicas de resumen de texto ([[Text Summarization]]) combinadas con la detección de "olores de código" ([[Code Smells]]) y "olores de pruebas" ([[Test Smells]]) para generar automáticamente comentarios de revisión en herramientas como [[Gerrit]].

## 4. Threats to Validity
- **Validez de constructo:** Mitigada mediante la triangulación de fuentes (análisis manual de 10 proyectos Java, integración de taxonomías de la literatura y validación con encuestas a desarrolladores).
- **Validez externa:** Limitada a proyectos de código abierto en Java (principalmente del ecosistema [[Eclipse]]) y a 52 desarrolladores en la encuesta principal.

---

## 5. Related Work
El trabajo se relaciona con investigaciones previas sobre procesos de [[MCR]], análisis de parches, métricas de calidad de software y el uso de herramientas de análisis estático de código ([[Static Application Security Testing|SAST]]).

---

## 6. Conclusions
Se propuso e investigó la taxonomía CRAM para entender los cambios en las revisiones de código modernas impulsadas por tecnologías en la nube y prácticas de integración/entrega continua ([[CI/CD]]). Los resultados muestran que los desarrolladores esperan una mayor automatización orientada a la documentación, la seguridad, el rendimiento y las configuraciones de despliegue.
